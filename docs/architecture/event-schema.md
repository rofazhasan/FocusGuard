# FocusGuard Event Schema Specification v1

## 1. Event Envelope

Every system event follows this standardized envelope:

```json
{
  "eventId": "evt_66a8bcaf37ac4c6b4a8be8ce",
  "type": "DOMAIN_BLOCKED",
  "deviceId": "dev_browser_chrome_01",
  "policyVersion": 42,
  "timestamp": 1723745834000,
  "payload": {}
}
```

| Field | Type | Description |
|-------|------|-------------|
| `eventId` | string | Globally unique event identifier. Format: `evt_<12-byte-hex>` |
| `type` | EventType enum | The event category (see section 2) |
| `deviceId` | string | Enrolled device identifier |
| `policyVersion` | number | Policy version active when event occurred |
| `timestamp` | number (ms epoch) | When the event occurred on the device |
| `payload` | object | Event-type-specific structured data |

### Enforcement Events

#### `DOMAIN_BLOCKED`
```json
{
  "payload": {
    "domain": "www.youtube.com",
    "policyId": "pol_abc123",
    "reason": "TIME_LIMIT_EXCEEDED",
    "usedSeconds": 1800,
    "limitSeconds": 1800,
    "action": "BLOCK"
  }
}
```

**reason values:**
| Value | Meaning |
|-------|---------|
| `TIME_LIMIT_EXCEEDED` | Daily budget exhausted |
| `SCHEDULED_BLOCK_ACTIVE` | Schedule-based blocking in effect |
| `FOCUS_MODE_ACTIVE` | Active focus session is blocking access |
| `EXPLICIT_BLOCK_RULE` | Unconditional block policy |

#### `APP_LIMIT_REACHED`
```json
{
  "payload": {
    "target": "com.google.android.youtube",
    "policyId": "pol_abc123",
    "usedSeconds": 1800,
    "limitSeconds": 1800
  }
}
```

## 3. Idempotency & Deduplication

Every event generated by a device contains a unique `eventId`. The server uses `eventId` as an idempotency key:

- If the same `eventId` is submitted multiple times (e.g. due to offline reconnection and re-sync), only the first is processed.
- The idempotency window is 48 hours.

## 4. Event Queue

Devices maintain a local event queue when offline. Queue properties:
- Maximum size: 5,000 events (overflow: oldest events are dropped and a `QUEUE_OVERFLOW` diagnostic event is generated)
- Stored in platform persistent storage (IndexedDB for browser extension, Room for Android, UserDefaults/SwiftData for macOS)
- Flushed on reconnection via `POST /usage/sync` or WebSocket `REPORT_EVENT`

## 5. Event Processing Order

Events are processed server-side in `timestamp` order within the same device. Cross-device event ordering for shared budget calculation uses the server receipt time as the secondary sort key when timestamps are equal.
