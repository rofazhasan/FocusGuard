## 1. Canonical Event Envelope

Every event produced by any FocusGuard client or ingested by the FocusGuard Cloud API must conform strictly to the **Canonical Event Envelope**:

```json
{
  "$schema": "https://focusguard.local/schemas/v1/event.json",
  "eventId": "evt_4a8b2c1d9e3f",
  "eventType": "USAGE_SESSION_ENDED",
  "deviceId": "c88aeef4-e2e6-4f8b-aaa5-bb62f348d272",
  "userId": "00000000-0000-0000-0000-000000000001",
  "timestamp": "2026-09-07T23:35:00.000Z",
  "schemaVersion": "1.0.0",
  "idempotencyKey": "c88aeef4:USAGE_SESSION_ENDED:1788804900:discord.exe",
  "payload": {}
}
```

### 1.1 Field Definitions

| Field | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `eventId` | String (UUID / `evt_*`) | **YES** | Unique identifier generated by the client or server. |
| `eventType` | String (Enum) | **YES** | One of the canonical 16 FocusGuard event types. |
| `deviceId` | String (UUID) | **YES** | RFC 4122 UUID of the originating device. Server sanitizes against authenticated claims. |
| `userId` | String (UUID) | **YES** | RFC 4122 UUID of the tenant owner account. |
| `timestamp` | String (ISO-8601 UTC) | **YES** | Exact UTC timestamp of the event occurrence. |
| `schemaVersion` | String | **YES** | Semantic version of the event schema (`"1.0.0"`). |
| `idempotencyKey` | String | **YES** | Deterministic hash or composite key preventing double ingestion. |
| `payload` | Object | **YES** | Event-specific typed data dictionary. |

## 2. Canonical Event Type Catalog & Payload Schemas

### 2.1 Usage Tracking Events

#### `USAGE_SESSION_STARTED`
Emitted when a user brings a target application or browser tab into active foreground.
```json
{
  "targetType": "APP",
  "targetValue": "discord.exe",
  "startedAt": "2026-09-07T23:30:00.000Z",
  "metadata": {
    "processPath": "C:\\Users\\User\\AppData\\Local\\Discord\\app-1.0.9001\\Discord.exe"
  }
}
```

#### `USAGE_SESSION_ENDED`
Emitted when the application loses focus, system idles (>60s), or workstation locks.
```json
{
  "targetType": "APP",
  "targetValue": "discord.exe",
  "startedAt": "2026-09-07T23:30:00.000Z",
  "endedAt": "2026-09-07T23:35:00.000Z",
  "durationSeconds": 300,
  "endReason": "FOCUS_LOST" // "FOCUS_LOST" | "SYSTEM_IDLE" | "SCREEN_LOCKED" | "APP_TERMINATED"
}
```

#### `USAGE_AGGREGATED`
Periodic rollup of usage deltas flushed from client offline queue.
```json
{
  "date": "2026-09-07",
  "syncSequence": 14,
  "usageDeltas": [
    { "targetValue": "discord.exe", "durationSeconds": 300 },
    { "targetValue": "youtube.com", "durationSeconds": 600 }
  ]
}
```

### 2.2 Policy & Enforcement Events

#### `POLICY_APPLIED`
Client confirms a policy version was successfully compiled and activated.
```json
{
  "policyId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "policyVersion": 4,
  "appliedAt": "2026-09-07T23:31:00.000Z",
  "activeRulesCount": 2
}
```

#### `POLICY_FAILED`
Client encountered a parse error or capability conflict while compiling policy.
```json
{
  "policyId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "policyVersion": 4,
  "errorCode": "CAPABILITY_UNSUPPORTED",
  "details": "Client platform EXTENSION cannot enforce target APP: discord.exe"
}
```

#### `LIMIT_WARNING`
User has exceeded 80% or 95% of their configured time budget.
```json
{
  "policyId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "targetValue": "youtube.com",
  "usedSeconds": 1500,
  "limitSeconds": 1800,
  "remainingSeconds": 300,
  "warningThresholdPercent": 83
}
```

#### `LIMIT_REACHED`
Budget exhausted (100% used). Triggers active enforcement.
```json
{
  "policyId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "targetValue": "youtube.com",
  "usedSeconds": 1800,
  "limitSeconds": 1800,
  "action": "BLOCK"
}
```

#### `ENFORCEMENT_STARTED`
Active restriction engaged (e.g. DNR rule enabled, window minimized, overlay displayed).
```json
{
  "targetType": "WEBSITE",
  "targetValue": "youtube.com",
  "actionTaken": "DNR_REDIRECT",
  "enforcedAt": "2026-09-07T23:32:00.000Z"
}
```

#### `ENFORCEMENT_SUCCEEDED`
Enforcement action verified by monitoring loop.
```json
{
  "targetType": "APP",
  "targetValue": "discord.exe",
  "verificationLatencyMs": 15
}
```

#### `ENFORCEMENT_FAILED`
Enforcement failed (e.g. process denied termination due to elevated privilege).
```json
{
  "targetType": "APP",
  "targetValue": "system_tool.exe",
  "errorCode": "ACCESS_DENIED",
  "fallbackActionTaken": "ATTENTION_OVERLAY"
}
```

### 2.3 Device & Synchronization Events

#### `DEVICE_ONLINE`
Client establishes authenticated WebSocket connection and verifies status.
```json
{
  "clientVersion": "1.0.0",
  "platformVersion": "Darwin 23.5.0",
  "capabilities": ["USAGE_TRACKING", "APP_RESTRICTION", "REALTIME_SYNC"]
}
```

#### `DEVICE_OFFLINE`
Clean client shutdown or socket disconnect detected by server heartbeat timeout.
```json
{
  "disconnectReason": "SOCKET_CLOSED",
  "lastSeenAt": "2026-09-07T23:34:00.000Z"
}
```

#### `DEVICE_REVOKED`
Device authorization permanently severed by account owner.
```json
{
  "revokedBy": "OWNER",
  "revokedAt": "2026-09-07T23:35:00.000Z"
}
```

#### `SYNC_STARTED` / `SYNC_COMPLETED` / `SYNC_FAILED`
Captures sync transactions for offline queue flush and cursor progression.
```json
{
  "syncCursor": "cur_v4_1788804900",
  "eventsUploaded": 12,
  "latencyMs": 45,
  "status": "COMPLETED"
}
```

## 3. Ingestion Idempotency & Replay Protection

### 3.1 Idempotency Key Composition
Clients compose `idempotencyKey` using:
$$\text{idempotencyKey} = \text{deviceId} + ":" + \text{eventType} + ":" + \text{eventTimestampSec} + ":" + \text{targetValue}$$

### 3.2 Server Deduplication Handling
1. Database enforces unique index on `(user_id, device_id, idempotency_key)` or `id`.
2. When a duplicate key arrives:
   - The server acknowledges the request with `HTTP 200 OK`.
   - Increments the `duplicates` counter in the batch response.
   - Discards the payload from database mutation and analytics calculation.
   - Does NOT broadcast redundant alerts over the WebSocket hub.

### 3.3 Offline Queue Recovery Scenario
```
Client accumulates 10 events offline.
Network restored -> Client sends POST /api/v1/events/batch.
Server processes & commits 10 events.
TCP ACK lost on client side (network timeout).
Client retries identical batch of 10 events.
Server detects 10 duplicate keys -> Returns HTTP 200 { processed: 0, duplicates: 10 }.
Client clears offline SQLite queue safely.
Analytics database remains 100% accurate without double counting.
```
